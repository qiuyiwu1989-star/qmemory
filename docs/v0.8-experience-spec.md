# QMemory v0.8 Experience Spec

## Product promise

QMemory automatically preserves work done in Codex and Claude Code, organizes it by project and
task, and lets the user inspect how evidence becomes reusable memory. The default experience is
an archive, not a memory inbox: users should not have to curate the system before it is useful.

## Concept decision

Three visual directions were explored under `assets/concepts/`:

- **A — Memory Workbench** supplies the default shell: persistent navigation, project metrics,
  one task per row, and a readable inspector.
- **B — Memory Atlas** becomes an optional relationship view for cross-Agent copies, subagents,
  and the L0–L3 chain. It is not the default because a graph is slower for routine browsing.
- **C — Evidence Timeline** supplies the task review pattern: raw messages remain primary, and
  derived memory visibly points back to evidence.

The implementation direction is **A shell + C evidence review + B optional map**.

## Information architecture

```text
QMemory
├── 工作台                 default
│   ├── project metrics
│   ├── task archive       one user task per row
│   └── task inspector
│       ├── L0 原始会话    default
│       ├── L1 原子记忆
│       ├── L2 项目场景
│       └── L3 稳定内核
├── 项目库                 automatic discovery and corrections
├── 候选记忆               review queue, secondary workflow
├── 正式记忆               active project judgments
└── 设置                   Agent connection, sync, diagnostics
```

## Layer contract

| Layer | Meaning | Default behavior | Evidence rule |
| --- | --- | --- | --- |
| L0 | Lossless source conversations | Always available and selected first | Original source remains immutable |
| L1 | Atomic facts, decisions, constraints, incidents | Generated as proposals | Every item must reference L0 |
| L2 | Project/task scenario and current working state | Generated asynchronously | Must list contributing L1/L0 inputs |
| L3 | Stable personal or project kernel | Rare, conservative updates | Must be editable and versioned |

L1–L3 never replace L0. A layer that has not been generated shows a natural empty state rather
than a count of pending work.

## Core interaction rules

1. **Automatic archival is ambient.** Show last sync and health, but do not make `同步` the primary
   daily task unless attention is required.
2. **A task is the primary browsing unit.** Agent names are source metadata, not separate rows.
3. **Raw evidence opens first.** Selecting a task always opens L0 at the most complete source.
4. **Source differences are explicit.** Coverage below 95% shows a notice; below 80% requires a
   strong warning and keeps every source reachable.
5. **Review is contextual.** Candidate memory should be reviewed beside the source message, not
   in an unrelated global queue. The global queue remains as a batch fallback.
6. **Progressive disclosure.** Routine browsing shows title, source, time, and state. IDs, hashes,
   merge reasons, and raw record counts move to source details.
7. **No memory pressure.** Empty candidate lists are a success state; do not imply the user has
   failed to maintain the system.

## Visual system

- Canvas: `#F4F5F8`; surface: translucent white; text: `#16181F`.
- Single interaction accent: `#5A4FE6`; green, amber, and red remain semantic only.
- Typography: Noto Sans SC for Chinese; Space Grotesk for Latin/product headings; JetBrains Mono
  for IDs and counts.
- Spacing follows a 4 px scale; common gaps are 8/12/16/24/32 px.
- Radius: 8 px controls, 12 px cards, 18 px major trays.
- Hierarchy comes from surface tone and hairline borders. Shadows are reserved for floating trays.
- Every selected, warning, and health state uses text or shape in addition to color.

## Key states to test

- No projects, empty project, one task, many tasks.
- One Agent source; Codex + Claude source copies; many subagent branches.
- Primary coverage 100%, 80–95%, and below 80%.
- No L1/L2/L3, proposed L1, confirmed L1, stale/superseded memory.
- Background sync active, current, failed, and source file changed during indexing.
- 980×650 minimum window and 1440×900 working size.
- Keyboard paths: project switch, search, task selection, layer selection, confirm, dismiss.

## Validation targets

- A first-time user can answer within 10 seconds: “How many projects and tasks are archived?”
- A user can open a task's most complete raw conversation in at most two actions.
- A user can find the evidence behind a candidate memory in at most three actions.
- No source copy or subagent becomes unreachable from the task inspector.
- Repeated archive sync is idempotent and does not change task counts without new source data.
