## 阻断风险

### P0：默认主会话可能隐藏大量有效内容

`问道 / 打造对话思维教练智能体` 被归成 4 个副本（Codex 2、Claude Code 2）。当前主会话只有 64 条可读消息，但四份副本去重并集有 654 个内容哈希，主会话覆盖率仅 9.8%，隐藏 590 个独有内容哈希。另一份 Claude 会话有 637 条，Codex 完整副本有 633 条。

根因边界：重复关系的 transitive union 把“短前缀副本”和“长续写副本”归为同一任务；canonical 选择更早、较短会话，详情却只读取 canonical。

验收：任何任务详情都不能因为 canonical 选择丢失成员中的独有可读内容。可以展示统一时间线，或明确默认选择覆盖率最高/最新的主副本，并让所有副本一键切换。阻断阈值：`primary_coverage < 95%` 时必须显示差异警告；`< 80%` 不允许默认只展示 primary。

### P0：同源重复未建模，任务列表会重复

现有 duplicate 算法明确跳过相同 `source_kind`。真实库存在大量同源高度重合样本，尤其是 Codex 多 Agent/续接：SkillOps 中至少三个根会话标题相同且内容重合约 99%，但会显示成多个任务；问道样本也包含 2 个 Claude 和 2 个 Codex 同源副本。

验收：同源“副本”和同一 parent 下的不同执行分支必须区分。不得仅凭首条用户消息和内容重合强合并子 Agent；根会话可建立 `same_source_copy` 候选关系，只有稳定来源标识或 >=95% 内容覆盖且时间相邻才自动合并。每个自动合并必须能解释、撤销，并保留原文件。

### P1：冻结字段语义需要固定

字段验收：

- `task_id`：稳定根任务 ID；增量同步、重启、排序、搜索前后不变。
- `title`：来自 primary 的第一条真实用户消息；清除系统上下文和秘密；120 字截断必须有完整 tooltip。
- `updated_at`：所有 task 成员的最大更新时间，不是 primary 更新时间。
- `project_root`：项目 canonical root；不能泄露临时 worktree 作为卡片主路径。
- `sources`：任务中顶层来源集合；subagent 不应虚增 Agent 来源。
- `source_copy_count`：顶层原始副本数，包括同源副本；不等于 `sources.length`。问道样本应为 4/2。
- `subagent_count`：沿 parent 链归入任务的执行分支数；不含重复副本。
- `readable_message_count`：默认阅读体验真实可访问的消息数；若只展示 primary，则不能把隐藏副本内容计入。
- `raw_message_count`：任务所有原文件解析消息数总和；允许包含重复内容，UI 必须标为“原始条数”。
- `merge_reason`：按每条边记录理由/置信度；不能只用“跨 Agent”笼统描述同源、续写、导入、parent 四种关系。
- `primary_conversation_id`：必须是当前默认阅读的副本；选择策略可解释且不造成内容损失。

## 搜索与同步体验验收

1. 搜索命中 duplicate 或 subagent 时，结果必须返回 `task_id`、来源、副本/分支标签和消息定位；不能让用户看到多个貌似重复的散落结果。
2. 中文、英文、多词、引号、FTS 特殊字符、空查询都不得静默返回空。当前异常分支吞掉 `sqlite3.OperationalError`，UI 需显示“查询格式不支持”并回退安全 LIKE/分词搜索。
3. 搜索结果默认排除工具调用、系统注入和 `<EXTERNAL SESSION IMPORTED>`；敏感内容在标题、摘要、匹配片段中必须脱敏。
4. 同步状态必须一次快照同时产出：扫描到、已导入、未变化、失败、项目、任务、原始会话、消息、开始/结束时间。页面各区域引用同一 `sync_run_id`，避免后台新增导致 139/141 之类跨区域不一致。
5. 增量同步幂等：同一源文件不变时连续同步，任务/副本/消息计数必须完全不变；追加时只增加新增消息；截断/改写时保留版本且不制造第二任务。
6. 项目卡区分“已发现但 0 会话”和“有会话项目”。首页项目数应说明口径，不能把空项目混入有档案项目。

## 建议的发布门槛

- 数据完整性：上述 8 类关系异常全部为 0；原始文件和消息数不因归组下降。
- 分组正确性：固定样本 task 数稳定；100% parent 分支可达其根任务；所有合并可展开原文件。
- 阅读完整性：任何任务默认视图都能访问 100% 非重复有效消息；primary 覆盖率告警规则通过。
- 搜索：固定中英文词在 root、duplicate、subagent 各命中 1 组，返回唯一 task 且可定位消息；错误查询不静默。
- 性能：23k 原始消息任务首屏不加载全部消息；项目列表和任务搜索需设实机预算并在发布前记录（建议 P95 列表 <300ms、首屏 <1s）。
- 同步：连续两次无变化同步计数完全相同；运行中 UI 展示同一快照 ID；单文件失败不影响其余文件且失败可见。

## 应补的纯测试夹具

1. 同源根会话 99% 重合但无 parent：验证副本候选而不是两个产品任务。
2. 短 canonical + 长续写 duplicate：验证默认阅读不丢长副本独有消息。
3. duplicate canonical 指向 subagent、orphan parent、parent cycle、cross-project parent：验证隔离、降级和诊断状态。
4. root -> subagent -> nested subagent：验证任意深度归根与 cycle guard。
5. FTS 特殊字符、中文短语、命中 duplicate/subagent：验证 task 聚合结果和消息定位。
6. 同步追加、截断、源文件移动、同一 native ID 多路径：验证幂等和版本保留。
