# QMemory 产品方法论：从工作证据到可复用记忆

状态：提案，待通过原型和试用验证。日期：2026-09-08。

## 产品承诺

自动保存不同 Agent 的工作证据，帮助用户回答：我当时要做什么、经历了哪些关键变化、为什么这样决定、最后得到什么、下次应该记住什么。

第一层用户价值是能找回完整工作过程；第二层是理解和复盘；第三层是将可靠记忆用于下一次工作。可视化与自动记忆共享同一套事实，不各自维护一份摘要。

## 三种身份和两种历史

项目是工作的范围，任务是一次目标及其推进过程，来源会话是某个 Agent 保存的一份记录。同一项目里的不同任务应独立展示；同一任务可以有多个来源、导入历史和执行分支。

归档中的“当前”是最近同步到的源文件版本；“历史”是源文件被改写或截断前保存的字节版本。历史文件可能包含当前版本没有的内容。

记忆中的“有效”是目前可用的判断；“历史”是被替代或归档的判断。两组状态互相独立：有效记忆可能引用一个旧的原始档案版本。

## 两个循环

工作循环：意图 → 探索与尝试 → 选择或转折 → 交付与验证 → 复用。

证据循环：采集 → 归属与关联 → 加工 → 审阅 → 召回 → 反馈与复核。

工作循环回答事情怎么发展；证据循环回答系统是否可靠地保存、理解和使用了这些事情。任务做完不代表证据加工完成；证据提炼完成也不代表项目目标完成。

## 共用对象

| 对象 | 职责 | 必须保留的属性 |
|---|---|---|
| Project | 隔离、目录与仓库别名 | 稳定 ID、历史别名、共享范围 |
| Task | 目标与工作状态 | 目标、状态及依据、成果、来源成员 |
| SourceVersion | 原始证据版本 | Agent、会话 ID、版本 hash、顺序、恢复清单 |
| EvidenceOccurrence | 同一内容在某个来源中的一次出现 | 原始角色、版本、消息标识或偏移、内容 hash |
| EvidenceSegment | 可引用的规范片段 | 多个来源出现位置、去重依据、共享/新增标识 |
| StoryBeat | 关键推进节点 | 类型、发生了什么、证据、时间、结果是否已验证 |
| Memory | 可复用判断 | 陈述、适用范围、有效时间、来源、确认状态、替代链 |
| Artifact | 实际交付 | 文件或链接、版本、可访问性、验证结果 |

相同内容 hash 是匹配线索，不单独证明两个事件是同一次发生。原文相同的“好的”应保留各次出现；来源角色也不能因导入包装而改写。

## 故事方法：起因、尝试、转折、结果、沉淀

1. 起因：用户的问题或目标是什么。引用最早的有效意图及后续修改。
2. 尝试：AI 和人各自推进了什么，包括失败和被放弃的方案。
3. 转折：谁在何时选择、否定或修正了什么，依据是什么。
4. 结果：实际留下了哪些文件、代码、决定或待办；区分已验证与仅声称完成。
5. 沉淀：哪些经验值得下次使用，适用范围和有效期是什么。

每个故事节点先显示一句标题、一句推进说明和来源数量。原话、详细经过和附件按需展开；选择节点后在固定侧栏阅读。默认一屏 5–7 个关键节点，可按阶段分组，不给每条消息生成一张卡。

未完成任务允许停在探索阶段。缺乏依据的总结明确标注“AI 整理，待核对”；没有结果就显示未完成。故事上的“决定”必须能找到明确选择，不能把 AI 建议写成人的拍板。

边的类型为：时间先后、导入、延续、分叉、支持、否定/替代、产出。时间先后不能自动标为因果。“促成了”这类因果关系需要证据，否则只写“随后”。

## 三个主要视图与一个证据抽屉

| 视图 | 用户的问题 | 主对象和交互 |
|---|---|---|
| 任务看板 | 我做过什么、卡在哪里、下一步是什么 | 按待开始/进行中/待我决定/已完成组织任务；独立标签显示归档、提炼、审阅状态 |
| 故事画布 | 这件事是怎么一步步变成结果的 | 从左到右显示起因到结果，探索分支侧向展开；支持“从头播放”、聚焦转折、来源筛选 |
| 记忆地图 | 我们已经知道什么、什么发生了变化 | 以主题或判断为节点，展开依据、适用项目、支持/冲突和替代关系；默认局部图 |
| 证据抽屉 | 这句话从哪里来、另一 Agent 是否还有独有内容 | 原文/来源差异/附件/版本切换；按需打开完整时间线 |

三种视图共享项目、任务、记忆 ID、搜索和筛选状态。切换视图后保持当前选择。图上的节点和看板卡片均可定位到同一个证据抽屉。

任务工作状态不能由 Agent 一句“完成”无条件决定，需展示推断依据，并允许用户修正。系统加工状态使用独立的“收件箱”：待归属、待提炼、待审阅、需处理、已整理。已整理可以产生零条记忆。

桌面信息布局：左侧项目导航；顶部全局搜索和真实同步状态；中部任务/故事/记忆视图切换；右侧固定证据抽屉。底部或设置页显示存储与后台队列，不抢占故事主线。

参考 demo 中意图、AI 贡献、人的选择和成果的语义色，但同时提供文字和图标。统一折叠卡高度，减少每张卡重复按钮。画布支持键盘顺序浏览、缩放重置和列表替代；紧凑窗口将侧栏改为覆盖抽屉。

## 跨 Agent 导入

Claude A 的历史 H 被 Codex B 导入后继续新增 D，形成一个任务的两个来源：共享 H 只用于一次展示和提炼，D 单独增量加工；源文件和出现位置均保留。

识别顺序：明确导入 ID/元数据 → 同项目内有序消息对齐 → 带上下文的片段覆盖率 → 不确定关联交由审阅。仅靠相似标题、时间接近或语义相似不直接合并。

提炼输入是任务所有来源与子分支的证据并集。处理缓存键包含证据内容版本、提炼器/规则版本与作用域，重复输入不得重复产生候选。保留分支上下文，避免把不同分支互斥的决定拼成共识。

## 原始数据治理

将原始字节、标准化证据、可重建索引、派生记忆分层。原始层可采用内容寻址对象、压缩和版本 manifest，需能够逐字节恢复源文件。

对重复内嵌图片可以保存原始编码字节对象，并在原位置记录引用；不要解码后重新编码图片或重新序列化 JSON 来冒充字节无损。清单保存顺序和每个原始版本的校验 hash。

存储去重和产品去重独立：一个文本在不同语境的多次发生可以引用同一存储对象，但仍保留多个事件。源文件包装不同也能共享证据，而不要求原始文件字节相同。

迁移流程：只读清点 → 隔离候选包 → 全量还原 hash 验证 → 与检索、版本和备份读写集成 → 并发/中断恢复验证 → 原子切换 → 回滚窗口 → 回收旧容器。GC 基于所有有效 manifest 的引用，不按旧文件年龄删除独有证据。

常规同步优先处理新追加字节。重写检查、大文件审计和历史回填进入限流后台队列；进度与失败原因可见。QMemory 自身治理与 Agent 源文件清理是不同边界。

## 同事试用与共享

同事独立安装个人库先行。团队共享使用明确的项目空间、成员权限和发布状态，默认发布已确认记忆及用户选择的证据；私人原文、自动生成故事和整个文件系统不随加入团队自动公开。

分享故事前预览可见节点、原文引用和附件范围，标明未知或未验证结果。撤销共享应停止后续授权访问，但不能承诺收回成员已下载的副本。

开源发布使用合成故事和跨 Agent 导入样本。个人真实对话用于本地验收，不进入公开仓库和 CI 日志。

## 验收方法

- 存储：迁移前后所有版本还原 hash 一致，引用定位不变；中断可恢复；报告实际回收量而不把候选压缩量当回收量。
- 去重：真实导入合并正确；后续独有消息和子分支不丢；相似但独立任务不误合并；支持撤销关联。
- 故事：所有关键节点有可打开的依据；选择不误归因；失败/分叉不被抹去；未验证成果不标已完成。
- 体验：在同事试用中，60 秒内说出目标、关键选择、结果和下一步，三次交互内找到某个决定的原话。记录失败原因再调整阈值。
- 记忆：在冻结样本上验证提炼准确率、来源覆盖率和召回帮助率；未通过前保持影子提炼/召回，不全量自动注入。
