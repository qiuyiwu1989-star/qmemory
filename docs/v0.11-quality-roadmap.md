# QMemory v0.11 — measurable memory loop

Status: in progress  
Release rule: the release is not ready until `qmemory quality-report --all-projects`
passes every gate on the agreed benchmark set.

## Outcome

Move QMemory from a conversation archive with derived candidates to a measurable Agent memory
substrate. QMemory remains the evidence and judgment system of record. TencentDB MemoryCore is
an optional, replaceable processor operating in shadow mode until recall quality is proven.

## Now — v0.11

### P0 identity and privacy

- Resolve a project by explicit binding, then canonical Git repository/worktree identity, then
  conversation working directory, with manual override as the recovery path.
- Keep source files immutable while allowing project attribution to be recomputed.
- Redact credential-shaped values before title, preview, search-index, log, and diagnostic use.
- Give every source scan a `sync_run_id` and structured per-source outcomes.

### P1 processor shadow mode

- Send only redacted user/assistant L0 evidence to MemoryCore.
- Keep MemoryCore L1/L2/L3 output proposed and read-only; never auto-confirm it.
- Record the recall plan but do not inject it into an Agent prompt while shadow mode is active.
- Fail open: MemoryCore unavailability must not block conversation capture or Agent work.

### Quality benchmark

- Freeze 30 representative tasks: 10 single-Agent, 10 cross-Agent, 10 large or branched.
- Label 3–5 supported atomic memories per task and at least 100 recall queries overall.
- Produce a machine-readable report covering provenance, duplicate rate, unsupported claims,
  content coverage, recall helpfulness, and latency.

## Next — after v0.11 gates pass

- Enable bounded recall for confirmed decisions, constraints, handoffs, and compact L3 only.
- Show why each memory was recalled and the exact source message.
- Collect helpful, ignored, and rejected feedback from both the UI and Agent protocol.
- Add expiry and review dates for transient status memories.

## Later

- Encrypted, content-addressed multi-device L0 sync and deterministic shard merge.
- Recovery drills and cross-device evidence-reference verification.
- Memory map and higher-order visualizations after the retrieval loop is demonstrably useful.

## Review cadence

- Daily automation: scan/import/failure counts, project attribution, extraction backlog, secret
  findings, relationship integrity.
- Weekly review: unassigned projects, unresolved duplicate tasks, yellow/red candidates, failed
  extraction, and unhelpful recall.
- Monthly consolidation: L1 dedupe, L2 aggregation, stale-state expiry, contradiction and
  supersession review.
- Quarterly audit: L3 core, restore drill, credential rotation, and benchmark regression.

## Release gates

The default machine gates are implemented by `qmemory quality-report`:

- event ledger and projections healthy;
- no duplicate canonical project roots;
- no unresolved exact-title task clusters or tasks below 80% primary coverage;
- at least 95% extraction coverage and no failed extraction left unresolved;
- at least 100 observed recalls;
- at least 30 ratings with a helpful rate of 70% or greater.

Manual benchmark gates remain mandatory:

- extraction precision at least 85%, and 95% for high-risk memory;
- 100% provenance and zero unsupported active memories;
- atomic duplicate rate no greater than 5%;
- contradiction/supersession detection at least 90%;
- recall Top-5 helpful rate at least 70%, irrelevant injection no greater than 5%;
- recall P95 no greater than 300 ms and memory failure never blocks an Agent;
- no credential-shaped values in title, preview, FTS, logs, or bridge state.
