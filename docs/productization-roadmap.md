# QMemory 产品化升级路线（提案）

日期：2026-09-08。配套方法：[产品方法论](product-methodology.md)。采用出口标准推进；版本号为拟议里程碑，不代表已经发布。

## 第一轮实施切片

以一个大型重写会话、一个 Claude→Codex 导入任务、一个普通单 Agent 任务作为端到端样本。交付可查看的空间报告与任务卡片，以及有来源的 5–7 节点故事原型。

数据路径：SourceAdapter → ArchiveStore → EvidenceIndex → ProjectRegistry/TaskResolver → Processor → MemoryLedger → RetrievalService。

界面：任务看板/故事画布/记忆地图 → 共用视图模型 → 统一服务 → 证据抽屉。先抽离归档、来源关联、加工接口，再拆大型界面文件；避免同时替换桌面框架与数据内核。

## 持续验收

1. 采集：新增消息及时出现，重复扫描零新增逻辑证据；失败可见且可重试。
2. 存储：原始版本可恢复，索引可重建，实际节省容量和恢复耗时可量化。
3. 归属：合并/拆分可撤销，导入消息不误标成人的新指令，普通相同短句不跨任务消失。
4. 提炼：在冻结任务集上至少 95% 已处理或明确跳过；来源 100%；准确率至少 85%，高风险至少 95%。明确将人工确认与 Agent 工作状态区分。
5. 召回：至少 100 个查询、30 次评价；Top-5 帮助率至少 70%；过期、冲突和越权记忆不得静默进入上下文。
6. 可视化：讲得清且可核实，视图切换保持任务选择与过滤状态；不把时间先后画成无依据因果。

## 开源与分发

沿用公开 MIT 仓库，补齐 CONTRIBUTING、合成测试语料、接口协议、迁移/兼容政策、隐私说明和版本变更记录。源码公开、签名安装包和团队数据服务分别验收。

对外展示固定版本演示数据与真实功能标记；MemoryCore 为可替换的可选处理器，未完成现场对比前不声称质量优于其他路径。
